# Finspire site — architecture and contracts

Finspire is the finance club of the IPM programme at IIM Ranchi. This repository is the club website, hosted on
GitHub Pages. It grew out of a single-page claude.ai artifact (kept outside this folder at `../src/finspire.src.html`);
that page becomes `src/home.html` here. New in this version: a Markets & News page, a Dictionary, a members-only
Library that opens Google Drive files inside the site, and Google sign-in restricted to `@iimranchi.ac.in` accounts.

Audience: IPM students starting out in finance. Copy is plain, direct and professional. Never use the words
"placement", "undergraduate" or "MBA" anywhere. Say "IPM" where a programme name is needed.

GitHub Pages serves a *project* site under a sub-path (`https://<owner>.github.io/<repo>/`). Therefore:
**every internal link and fetch is relative**. Each HTML page declares its depth with
`<meta name="fs-root" content="../">` (sub-pages) or `content="./"` (home). JS builds URLs with `Finspire.url(path)`.
Never write a leading `/` in an internal URL. `tests/integrate.test.mjs` serves the build under a sub-folder and fails on
any internal link that leaves it.

Local preview: `python3 scripts/build_site.py --out .dev/<name>` then `python3 -m http.server <port> -d .dev/<name>`.
Use your own `.dev/<name>` folder and your own ports so parallel work never collides.

## Design language (must match the home page)

Dark, calm, Mercury-like. Charcoal + Finspire red, IBM Plex Sans / IBM Plex Mono, self-hosted: the latin woff2 files live
in `site/assets/fonts/` (Sans is one variable file for weights 300–700, Mono 400 and 500), declared with `@font-face`
(`font-display:swap`, latin `unicode-range`) at the top of pages.css and of the home `<style>`; every `<head>` preloads
the Sans file and Mono 400 before its stylesheets and loads nothing from Google Fonts. "Plex Sans Fallback" (Arial) and
"Plex Mono Fallback" (Menlo) carry Plex's metrics (`size-adjust`, `ascent-override`, `descent-override`), so text set
before the files arrive has the same widths and line boxes and nothing reflows. Tokens:

Buttons: `.btn` pill 46px (`.sm` 38px), `.btn-primary` red, `.btn-ghost` outline, `.btn-ink`. Eyebrow labels: mono 12px,

`view-transition-name: fs-header` on the header and `fs-logo` on the header logo only (a second element with the same name,
e.g. the footer logo, makes the browser skip the transition). The root uses the browser's default cross-fade (0.25 s),
which never dips the dark background, so there is no flash between pages. The nav row (logo, link sizes and spacing,
Join button, breakpoints at 1279/1139/960 px) is identical on the home page and the sub-pages; only the home page adds
the slim announcement bar above it and keeps the header transparent over its hero until scrolled.

## Shared header (sub-pages) and navigation

Primary nav, same order everywhere: **Start here** (`index.html#paths`), **Repository** (`index.html#repository`),
**Markets** (`markets/`), **Dictionary** (`dictionary/`), **Library** (`library/`), **Events** (`index.html#events`).
Right side: the account control (`Finspire.ui.mountAccount(el)`) and **Join Finspire** (LinkedIn, red button, `aria-label`
"Join Finspire on LinkedIn (opens in a new tab)"). Below 960px the links collapse into a 44px burger menu whose last row
is the same red button reading "Join on LinkedIn ↗"; the page is scroll-locked while it is open. `config.js` is loaded
in `<head>` with a one-line script that adds `html.fs-signin` when a client id is set, so the account slot is reserved
before finspire.js renders the Sign in pill (no sideways nudge on load). The footer has the same five columns on every
page (Repository, Start here, Tools, Club, Follow); the home fills the first two from site-data, sub-pages carry the names. The current page's link gets `aria-current="page"`.
Sub-page header markup lives in `site/_template.html` (written by the shell); page authors copy it verbatim.

## window.FINSPIRE_CONFIG (site/config.js)

```js
window.FINSPIRE_CONFIG = {
  googleClientId: "",                 // OAuth 2.0 Web client id; empty = sign-in shows "not switched on yet"
  allowedDomain: "iimranchi.ac.in",   // only these accounts may sign in
  driveApiKey: "",                    // optional fallback for folders shared "anyone with the link"
  admins: [],                         // emails allowed to see Edit mode on the home page
  github: { owner: "", repo: "", branch: "main" },  // where Edit mode commits data/site-data.json
  siteUrl: "",                        // public URL once deployed (used by the news archive merge)
  marketsPollSeconds: 15,
  newsPollSeconds: 180,
  // optional (defaults shown): switch pages off for a partial launch, and say where each page lives
  features: { markets: true, dictionary: true, library: true, signin: true },
  pages: { home: "index.html", markets: "markets/", dictionary: "dictionary/", library: "library/" }
};
```

### Feature switches and the sign-in rollout rule
`Finspire.feature(name)` reads `cfg.features`. Links to a switched-off page (and any `[data-feature="<name>"]`) are
hidden. **`feature("signin")` is true only when sign-in can actually work**: `features.signin` is not false AND
`googleClientId` is set (or local demo mode is on). Until an admin pastes the client id:
- there is no account control and no sign-in prompt anywhere (no button that leads to "not switched on");
- `Finspire.auth.user()` returns the local guest `{sub:"guest", guest:true}`, so saved words, history, revision and
  "Your words" in the news work and are kept in this browser (`fs:guest:*` keys);
- the Library shows "Opens with IIM Ranchi sign-in" and says it opens once IIM Ranchi sign-in is switched on (unless
  `driveApiKey` lets it browse folders shared "anyone with the link"); home Drive cards open Google Drive directly;
- once sign-in is configured, the guest's local data (history, saved, revision, library recents/positions) merges into
  the account at first sign-in and the guest keys are cleared.

## Data contracts

### Glossary source entry (content/glossary/*.json — each file is a JSON array)
```json
{"id":"repo-rate","term":"Repo rate","cat":"central-banks","level":"b",
 "aliases":["repurchase rate","policy repo rate"],
 "hl":["repo rate","repo rates","policy repo rate"],
 "abbr":[],
 "short":"The interest rate at which the central bank lends overnight money to banks against government bonds.",
 "kid":"…1–3 tiny sentences a three-year-old could follow…",
 "detail":"…80–150 words…",
 "example":"…concrete worked example…",
 "formula":"",
 "related":["Reverse repo rate","Monetary policy","Standing deposit facility"]}
```
`id` slug [a-z0-9-]; `level` b|i|a; `hl` = lowercase phrases safe to auto-highlight in news (case-insensitive, whole
words); `abbr` = case-sensitive acronyms (e.g. "GDP", "RBI"); `related` = term names (resolved to ids at build).

### Built glossary (dist/data/glossary/) — v2
`index.json`: `{"v":2,"n":<count>,"cats":{"<cat>":{"name":"…","n":<count>}},"t":[[id,term,cat,level,short,aliases[],[],abbr[]],…],
"shards":{"<cat>":[<first id of part 2>, <first id of part 3>, …]}}` (slot 6 stays empty: the highlight phrases moved out)
`phrases.json`: `{"v":2,"hl":{"<id>":[phrase…]}}` — fetched alongside the index, only needed to underline text
`entries/<cat>.json`, `entries/<cat>-2.json` …: `{"<id>":{"kid":"…","detail":"…","example":"…","formula":"…","related":[ids]}}`,
entries sorted by id and split into ≤ 60 KB parts; part n holds ids ≥ shards[cat][n-2] (part 1 keeps the plain name)
`tod.json`: `{"v":1,"tz":"Asia/Kolkata","days":{"YYYY-MM-DD":{id,term,cat,catName,level,short,kid}}}` for yesterday, today and
tomorrow IST, the same pick as `Finspire.glossary.termOfDay` (rebuilt by the 15-minute workflow)
`meta.json`: `{"n","cats"}`
Python consumers (`scripts/fetch_news.py`) read the index through `load_glossary()`, which merges phrases.json back into
slot 6 so the term matcher sees what the pages see.

## Pages (what each must do)

**Markets & News (`markets/`)** — a scrolling live ticker under the header; a markets board grouped India · Americas ·
Europe · Asia-Pacific (cards: name, last, change, % change, day-range bar, open/closed pill); a rates board (policy rates
table: RBI repo/SDF/MSF/CRR/SLR, US Fed funds target range, ECB deposit rate, Bank of England Bank Rate, BoJ and PBoC from
the manual file — each with as-of date; live government bond yields; U.S. Treasury yield curve chart latest vs 1 month vs
1 year ago with a plain explainer of normal/flat/inverted); commodities, currencies, crypto. Every instrument label has a
dictionary tooltip. Polls live sources every 15 s while visible; values flash on change. Below: the live news feed on a
light band — region tabs, market chips, search, "Concepts in today's news" strip, cards with highlighted terms and concept
chips, a one-line "Why it matters" lens per primary market tag, "N new stories" pill on refresh.

**Dictionary (`dictionary/`)** — big search, categories with counts, A–Z, term of the day; entry view with Plain meaning ·
Like I'm three · In detail · Example · Formula · Related · In the news (from news-terms.json). Deep link `#t=<id>`.
Signed in: Recent lookups, Saved words, Revise (quiz with spaced repetition). Signed out: browsing and search work; the
personal panel invites sign-in.

**Library (`library/`)** — members only. Signed out: a gate explaining IIM Ranchi sign-in. Signed in: "Open the library"
(gets a Drive token on click) → folders from data/site-data.json `drive.folders` (folder id parsed from each `u`). Deep
link: `library/#f=<folder id>[/<sub id>…]`; `library/?f=<folder id>` (used by the home page's Drive cards) is turned
into the hash form on load. Files
listed through the Drive API, breadcrumb into sub-folders, search, recent files. Viewer opens inside the page: PDFs with
PDF.js 4.10.38 from cdnjs (`isEvalSupported:false`), Google Docs/Slides/Sheets exported to PDF, images inline, other
types in the Drive preview iframe; download button everywhere; remembers the last page per file. Upload to the club
inbox (`drive.inbox`) with the drive.file scope.

**Home (`src/home.html`)** — the existing page, unchanged in look, plus: new nav + account control; a compact "Markets &
News" section (live mini-board, three latest headlines with terms highlighted, term of the day, buttons to the Markets
page and the Dictionary); Drive cards open the Library (`library/?f=<folder id>`) instead of Google Drive whenever the
Library can open files (sign-in usable or `driveApiKey` set), otherwise Google Drive directly; Edit mode (admins only) saves
`data/site-data.json` to GitHub through the contents API with a token the admin pastes once (stored only in that
browser), instead of the artifact publish.

## Inter-page widgets (used by the home page)

`site/assets/js/markets.js` defines `window.FinspireMarkets = { mountTicker(el), mountMini(el, ids) }` and
`site/assets/js/news.js` defines `window.FinspireNews = { mountTeaser(el, {count}) }`. Both work on any page whose
`fs-root` is set, start/stop polling with page visibility, and style themselves with classes from
`site/assets/css/markets.css` (all markets classes prefixed `mk-`, all news classes prefixed `nw-`, so they never collide
with the home page's own CSS). The home page links `assets/css/markets.css` and calls:
`FinspireMarkets.mountMini(el, ["NIFTY","SENSEX","SPX","US10Y","BRENT","USDINR"])`, `FinspireNews.mountTeaser(el, {count: 3})`,
`FinspireMarkets.mountTicker(el)` (optional slim ticker).

## Term matching (same rules in JS and Python)

Highlight phrases (`hl`) match case-insensitively, acronyms (`abbr`) case-sensitively, both on word boundaries
(letters/digits on either side block a match), longest phrase first, no automatic plurals (inflections are listed in the
data). Each term is highlighted at most once per headline+snippet.

## Local-only test hooks

`?demo-user=1` (fake signed-in student) and `?demo-drive=1` (Library reads `_demo/drive.json` and files under `_demo/`
instead of Google Drive) work only on localhost/127.0.0.1 and only when the build was made with
`scripts/build_site.py --demo`. Files and folders whose names start with `_` inside `site/` are never deployed.
